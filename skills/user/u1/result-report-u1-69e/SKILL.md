# 우선협상 결과보고 및 계약체결 팩

- 상속: corp:koscom-hwp-report. 전사 지침은 그대로 따르고 아래만 덧붙인다.
- 기반 양식: 기안문(`preset: draft`) — 기안문 양식의 머리(수신자 · 제목) · 관련 근거 · 요청 문장 · 「아래」 · 번호 항목 · 첨부 · 결재 칸.
- 형식: 한글
- 문체: 전사 보고 문법(명사형 종결 · 2026. 10. 28 · 90자). 「관련 근거」 장은 문서 제목을 그대로 옮긴 인용이라 길이 · 끝말 검수에서 빠진다(앱 aacaeef 이후).
- 구성: 관련 근거 → 입찰진행 → 입찰결과 → 사업발의부서 협상결과 → 계약체결.

## 문서 모양

```
수신자 : 내부결재
제  목 : (사업명) [품목n]- (입찰건명) 제한경쟁입찰(협상에의한계약) 우선협상 결과보고 및 계약체결
1. 관련 근거
   가. 사업 추진 문서  나. 입찰 실시 문서  다. BMT 결과 통보  라. 제안평가 결과 보고
   마. 제안평가 결과 통보 및 협상절차 진행 요청  바. [사내메일] 협상결과 통보
2. 위 근거에 의거, (입찰건명) 제한경쟁입찰(협상에 의한 계약) 우선협상 결과보고 및 계약체결을 아래와 같이 진행하고자 합니다.
- 아 래 -
1. 입찰진행        표: 일정 · 일시 · 참가업체 · 비 고 (제안요청설명회 ~ 협상결과 통보 5행)
2. 입찰결과        (단위 : 원, 부가세 별도)  표: 낙찰업체 · 사업예산 · 제안금액 · 예산대비율
3. 사업발의부서 협상결과   ㅇ 협상결과 통보일 : …(사내 메일)  ㅇ 협상결과 : 협상대상자인 '…'이 …
4. 계약체결        ㅇ 계약명  ㅇ 계약내역(…) + 표  ㅇ 계약금액  ㅇ 계약보증금  ㅇ 계약처  ㅇ 납품기한
                   ㅇ 지체상금  ㅇ 하자보증기간 및 무상보증기간  ㅇ 하자보증금  ㅇ 대금지급
                   ㅇ 검사자(내부감사부 입회) + 표 + ※ 후임자 승계  ㅇ 계정과목
첨부 1. 관련 근거 문서 … 6. [사내메일] … 7. 우선협상결과 보고서 8. 물품구매계약서 9. 견적서 10. 확약서. 끝.
(결재 · 협조 · 시행 칸 — 전자결재 영역, 마지막 쪽 아래)
```

## 값을 찾는 곳

| 칸 | 자료 |
|---|---|
| 관련 근거 · 첨부의 문서번호 · 시행일 | 업로드한 문서의 시행 칸(「시행  부서2026-0000  (YYYY. M. D.)」), 비었으면 그 문서를 인용한 다른 문서의 관련 근거 줄 |
| 제안평가 결과 보고(문서번호 없음) | 제안평가 결과 통보 문서의 관련 근거 |
| 입찰일정(제안요청설명회 · 입찰참가등록마감) · 사업예산 · 입찰내역 표 | 입찰 실시 문서 |
| 우선협상대상자 · 참가업체 수 · 제안금액 | 제안평가 결과 통보 문서 |
| 납품기한 · 하자보증기간 · 대금지급 · 검사자 표 · 계정과목 | 사업 추진 문서(계약 조건 · 검사자 · 예산 현황) |
| 협상결과 통보일 · 메일 제목 | 요청 글(자료에 없으면 「(확인 필요)」, 메일 근거 · 첨부는 쓰지 않음) |
| 예산대비율 · 계약금액 · 계약보증금 · 하자보증금 | 계산(제안금액 ÷ 사업예산, 제안금액 × 1.1, 계약금액의 10/100 · 3/100) |

## 서식과 앱이 만드는 부분
- 「1. 관련 근거」 → 가. 나. …, 「2. 」 번호, 「- 아 래 -」, 장 번호, 표 위 단위 줄, 「※」 참고: 렌더러가 붙인다.
- 요청 문장: 설계도의 `request`를 그대로 쓴다(앱 aacaeef 이후). 「…을 추진하고자 하오니 결재하여 주시기 바랍니다」가 아니라 이 문서의 꼴(「…을 아래와 같이 진행하고자 합니다.」)로 쓰기 위해서다.
- 계약내역 · 검사자 표: 그 항목의 `table`로 넣으면 항목 바로 아래(하위 「-」 뒤, 「※」 앞)에 그린다(앱 aacaeef). 표를 여는 줄은 표와 같은 쪽에 둔다(한글 스킬 7c9432a).
- 업로드한 첨부 파일: AI가 첨부 목록에서 빠뜨리면 앱이 파일 이름(확장자 뺌, 밑줄 그대로)으로 붙인다. 문서번호로 같은 문서임을 알아보고 두 번 적지 않는다.
- 결재 · 협조 · 감사 · 시행 · 주소 칸: 전자결재 시스템 영역이라 양식 그대로 둔다. 결재 칸은 마지막 쪽 아래에 붙고, 첨부 목록과 같은 쪽에 온다.

## 고정 문구(글자 그대로)
- (없음) — v1.x는 대표 문서의 장 · 표 머리 · 결재란 글을 고정 문구로 두어, 요약보고 서식에 표 머리 글이 항목으로 흩어졌다. 표 머리와 반복 문장(지체상금 · 대금지급 · 후임자 승계 · 협상결과 문장)은 작성 규칙으로 옮겼다.

## 작성 규칙
- 이 문서는 제한경쟁입찰(협상에 의한 계약)에서 사업발의부서가 우선협상대상자와 협상을 마친 뒤 계약담당부서가 협상 결과를 보고하고 계약 체결을 결재받는 내부결재 기안이다. recipient는 「내부결재」. title은 입찰 실시 문서 제목의 사업명 · 품목 · 입찰건명으로 「(사업명) [품목n]- (입찰건명) 제한경쟁입찰(협상에의한계약) 우선협상 결과보고 및 계약체결」 꼴로 쓴다. 품목 구분이 없으면 「[품목n]- 」을 뺀다. purpose는 「(입찰건명) 제한경쟁입찰(협상에 의한 계약) 우선협상 결과보고 및 계약체결」, request는 「위 근거에 의거, (purpose)을 아래와 같이 진행하고자 합니다.」로 쓴다.
- 관련 근거는 입찰이 진행된 순서(시행일 순)로 쓴다: 사업 추진 문서 → 입찰 실시 문서 → BMT 결과 통보 → 제안평가 결과 보고 → 제안평가 결과 통보 및 협상절차 진행 요청 → 협상결과 통보 메일. 문서번호가 있으면 '문서번호(시행일 : 문서 제목)', 없는 보고는 '문서 제목(시행일)', 메일은 '[사내메일] 메일 제목 (받은 날)'. 문서 제목은 고치지 않고 옮기고, 요청 · 자료에 없는 문서와 메일은 지어내지 않는다.
- 입찰진행은 항목 없이 표 하나(일정 · 일시 · 참가업체 · 비 고, 5행), 입찰결과는 항목 없이 표 하나(낙찰업체 · 사업예산 · 제안금액 · 예산대비율, 단위 「(단위 : 원, 부가세 별도)」)다. 예산대비율은 소수 둘째 자리까지 반올림한다.
- 사업발의부서 협상결과는 「협상결과 통보일 : …(사내 메일)」과 「협상결과 : 협상대상자인 '…'이 첨부와 같이 협상조건을 전부 수용함에 따라 최종 낙찰자(계약상대자)로 선정(첨부 협상결과 참조)」 두 항목이다. 결과가 다르면 요청 · 자료대로 쓴다.
- 계약체결은 계약명 → 계약내역(표) → 계약금액 → 계약보증금 → 계약처 → 납품기한 → 지체상금 → 하자보증기간 및 무상보증기간 → 하자보증금 → 대금지급 → 검사자(내부감사부 입회)(표 + ※ 후임자 승계) → 계정과목 순서다. 계약내역 표는 입찰내역 표를 옮기고 금액 칸에 제안금액을, 검사자 표는 사업 추진 문서의 검사자 표에서 다른 품목 전용 행만 빼고 옮긴다.
- 계약금액은 제안금액 × 1.1(원 단위 반올림, 부가세 포함), 계약보증금은 계약금액의 10/100, 하자보증금은 3/100(둘 다 「지급각서 대체징구(당사 협력업체)」 병기), 지체상금은 「지체일수 1일당 계약금액의 1.5/1000」이다.
- 협상결과 · 계약체결 장의 항목은 라벨 칸을 비우고 「항목 이름 : 내용」을 통째로 쓴다(「하자보증기간 및 무상보증기간」처럼 이름이 라벨 칸보다 길다).
- 첨부는 관련 근거 문서 → 협상결과 메일 → 우선협상결과 보고서 → 물품구매계약서 → 견적서 → 제조사의 물품공급 및 기술지원 확약서 순서로 「문서명 1부」 꼴로 쓰고, 업로드한 파일은 하나도 빼지 않는다.
- 날짜는 'YYYY. M. D.', 금액은 원 단위 숫자에 쉼표, 회사 이름의 「주식회사」는 「㈜」로 쓴다.
- 규칙 원문(예시 포함)은 `kosoe-skill.yaml`의 `rules`에 있다.

## 만든 방법 · 검증
- v1.0.0 ~ v1.1.1은 앱의 스킬 만들기로 대표 문서 1건에서 만들었다. 기반 양식이 결과보고(요약보고 서식, 유사도 0.0)로 잡혀 기안문 머리 · 관련 근거 · 결재 칸이 요약보고 박스로 나왔다. 장 · 표 머리 · 결재란 글이 고정 문구로 들어갔고, 문체 검사는 미통과인 채로 강제 등록되었다.
- v2.0.0은 기안문 서식(`preset: draft`)으로 다시 만들었다. 구성은 기안문 양식대로 「관련 근거」 + 번호 항목 4개다. 고정 문구는 작성 규칙으로 옮겼고, 값마다 찾는 자료와 계산식을 규칙에 적었다. 대표 문서의 값(문서번호 · 금액 · 업체 · 부서)은 저장소에 올리지 않고 규칙 예시는 지어낸 값으로 썼다.
- 검증: 관련근거 문서 4건(사업 추진 · 입찰 실시 · BMT 결과 통보 · 제안평가 결과 통보, 기안문 양식으로 다시 만든 한글 파일)을 앱에 올리고 짧은 요청(협상결과 메일 날짜 · 제목)을 주어 만들었다. 결과는 다음과 같다.
  - 검수 모두 통과.
  - 대표 문서와 줄 단위로 93줄 중 65줄이 같다. 다른 줄은 기안문 양식에 맞춘 날짜 꼴(2026. 9. 16.) · 「아래」 · 표 단위 줄 · 「관련 근거」 띄어쓰기와 원본 자료와 다른 대표 문서의 표기다.
  - 요청 글 없이 첨부만 주면 협상결과 통보일은 「(확인 필요)」로 두고, 메일 근거 · 첨부는 쓰지 않는다.
- 대표 문서보다 쪽이 하나 많다(4쪽). 기안문 양식대로 ㅇ 항목 사이에 빈 줄을 두기 때문이다. 결재 칸은 첨부 목록과 같은 마지막 쪽에 있다.
