# PB 전산서비스 추가업무 이용 견적서

제목 · 표 머리 · 글꼴 · 테두리 · 쪽 구성은 서식 파일에 들어 있다. Claude가 할 일은 **칸에 넣을 값을 모아 `values.json`으로 정리**하고 **렌더러를 돌려 결과를 확인**하는 것뿐이다. 서식의 글을 새로 쓰거나 고치지 않는다.

```
사용자가 준 값 → values.json → scripts/render.py → 견적서.xlsx → show.py(· preview.ps1)로 확인 → 전달
```

## 준비물

- Python 3과 `openpyxl` · `pillow` (`pip install openpyxl pillow`. pillow가 없으면 서식의 회사 로고가 빠진다)
- (권장) 엑셀 — 결과를 화면으로 확인할 때
- 이 스킬 폴더를 `<SKILL>`이라 부른다.

## 작업 순서

### 1. 값 모으기

`form.yaml`이 칸의 정본이다. 필수 칸이 빠졌으면 사용자에게 묻는다. 짐작해서 채우지 않는다.

| 칸 | 필수 | 예 | 들어가는 곳 |
|---|:---:|---|---|
| `고객사명` | ✓ | E증권 | 수신처(뒤에 "귀중"이 붙는다) |
| `추가업무명` | ✓ | 고객확인 모니터링 고도화 | 견적명, 표 제목의 괄호 안 |
| `견적일자` | ✓ | 2026년 01월 15일 | 견적 일자. 따로 말이 없으면 오늘 날짜를 `YYYY년 MM월 DD일`로 |
| `유효기간` | | 견적 후 1개월 | 유효 기간(없으면 이 기본값을 넣는다) |
| `대표이사` | | 김 철 수 | 공급자 이름. 글자 사이를 띄운다 |
| `RM담당` · `계약담당` | | 금융영업부 홍길동 차장 (02-000-0000) | 「2. 기타」의 담당자 줄. 비우면 그 줄이 빠진다 — 둘 중 하나는 넣는다 |

이용료 표는 `rows.이용료`에 행마다 `대분류 · 중분류 · 소분류 · 회사기본 · 영업점당 · 이용량 · 비고`를 적는다. 금액 단위는 **천원/년, 부가세 별도**다. 값이 없는 금액 칸은 `-`를 넣는다. 합계는 `회사기본`을 더해 자동으로 들어간다 — 따로 적지 않는다. 행은 7개까지 한 쪽에 들어간다(그보다 많으면 `WARN`이 나온다).

### 2. values.json 쓰기

[`examples/values.example.json`](examples/values.example.json)을 본뜬다.

```json
{
  "fields": {"고객사명": "E증권", "추가업무명": "고객확인 모니터링 고도화", "견적일자": "2026년 01월 15일",
             "유효기간": "견적 후 1개월", "대표이사": "김 철 수",
             "RM담당": "금융영업부 홍길동 차장 (02-000-0000)", "계약담당": "금융영업부 이영희 차장 (02-000-0001)"},
  "rows": {"이용료": [{"대분류": "영업지원", "중분류": "AML", "소분류": "고객확인 모니터링 고도화",
                       "회사기본": "18,000", "영업점당": "-", "이용량": "-", "비고": "- 가동 다음 달부터 청구"}]}
}
```

### 3. 만들기

```
python <SKILL>/scripts/render.py values.json "E증권_PB전산서비스 추가업무(고객확인 모니터링 고도화)이용 견적서_20260115.xlsx"
```

파일 이름은 원본처럼 `고객사명_PB전산서비스 추가업무(추가업무명)이용 견적서_YYYYMMDD.xlsx`로 짓는다. 표준출력이 `OK <경로>`로 끝나면 성공이다. `WARN [칸] 값이 없어 비워 둠`이 나오면 그 칸이 비어 인쇄된다 — 사용자에게 알린다.

### 4. 확인

```
python <SKILL>/scripts/show.py 견적서.xlsx
```

칸 값 · 표 행 수 · 합계를 글로 보여 주고, 채워지지 않은 토큰이 남았으면 `LEFT …`로 알린다. Windows에 엑셀이 있으면 화면도 본다.

```powershell
<SKILL>\scripts\preview.ps1 -File 견적서.xlsx -OutDir shots
```

캡처에서 볼 것: 수신처, 견적명(두 줄을 넘지 않는지), 표의 행 수와 합계, 담당자 줄, 바깥 테두리가 한 쪽 안에 있는지.

## 직인

서식에는 직인 그림이 없다. 견적서는 **직인 자리를 비운 채** 만들고, 날인은 사내 절차대로 하라고 알린다. 사용자가 자기 PC에 있는 직인 그림 파일의 경로를 직접 줄 때만 넣는다.

```
python <SKILL>/scripts/render.py values.json 견적서.xlsx --image 직인=C:/내폴더/직인.png
```

그 그림 파일을 이 스킬 폴더나 저장소로 복사하지 않는다. 직인 그림을 찾아다니거나 만들어 내지 않는다.

## 하지 않는 것

- 서식의 글(제목 · 인사말 · 표 머리 · 단위)을 바꾸지 않는다. 표 구성이 달라져야 하면 이 스킬의 범위가 아니다 — 서식을 새로 만든다(아래).
- 금액을 계산해 지어내지 않는다. 사용자가 준 금액만 쓴다. 합계만 자동으로 더한다.
- 실제 고객사명 · 금액 · 담당자 이름과 전화번호를 이 스킬 폴더(예시 · 평가 자료)에 남기지 않는다. 예시는 모두 가상이다.

## 서식을 고치거나 새 견적서 스킬을 만들 때

`scripts/make_template.py`가 실제 견적서(.xls · .xlsx)를 칸 토큰이 든 서식으로 바꾼다. 문서마다 바뀌는 글을 `{{칸 이름}}`으로 바꾸는 바꿈표(tsv)를 쓰고 돌린다. **원본 문서와 바꿈표는 저장소에 넣지 않는다**(`_private/`에 둔다).

```
python <SKILL>/scripts/make_template.py --inspect 원본.xls                     # 셀 주소 · 글 · 그림 목록
python <SKILL>/scripts/make_template.py 원본.xls 바꿈표.tsv <SKILL>/templates/새서식.xlsx
```

바꿈표 형식과 토큰 규칙은 [`references/template_guide.md`](references/template_guide.md)에 있다. 표 구성이 다른 견적서는 이 폴더를 본떠 **목적마다 스킬을 따로** 만든다.
