# source.json 작성 지침 (gian/1.0)

`build.js`가 읽는 기안문 원천이다. 스키마는 [gian.schema.json](gian.schema.json), 완성 예시는 `examples/edr/source.json`이다.

## 최상위

| 키 | 내용 |
| --- | --- |
| `schema` | `"gian/1.0"` |
| `header` | `{recipient, title, kind}` |
| `basis` | 관련근거 배열. 없으면 `[]`(요청 문장이 `1.`이 된다) |
| `purpose` 또는 `request` | 요청 문장 |
| `closing` | 선택. "- 아 래 -" 줄을 바꿀 때만 |
| `sections` | 번호 항목 배열 |
| `attachments` | 첨부 목록 |
| `approval` | 결재선·협조 |
| `footer` | 시행번호·연락처 |
| `sender` | 선택. 외부로 보내는 공문의 발신명의(예: "코스콤 대표이사") |

## header

- `recipient`: 내부에서 결재받는 기안은 `"내부결재"`, 계약·구매를 맡기는 기안은 맡는 부서장(예: `"경영지원부장"`)이다.
- `title`: 사업명 뒤에 할 일을 붙인다. 예: "OOO 도입 및 구매 계약 의뢰", "OOO 기본계획 수립 및 입찰 시행", "OOO 결과 보고".
- `kind`: `기본계획`, `기본계획+집행`, `보고`처럼 분류를 적는다. `해지`나 `변경`이 들어가면 맺음 줄이 "- 다 음 -"이 되고, 끝 문장이 "~하고자 합니다."가 된다.

## basis (관련근거)

- 첨부된 공문(scan의 `gian`·`letter`)마다 1건씩 만든다: `{"mark": "가", "docNo": "시행번호", "date": "YYYY-MM-DD", "title": "공문 제목", "attachRef": 첨부번호}`.
- 첨부 공문 본문이 인용하는 상위 문서(그 공문의 관련근거 줄)도 근거로 쓸 수 있다. 이때는 `attachRef`를 넣지 않는다. 첨부에 없는 문서번호는 check가 WARN을 낸다.
- 1건이면 "1. 관련근거 : …" 한 줄이 되고, 2건 이상이면 가·나·다로 나뉜다.

## purpose / request

- `purpose`는 "~을 추진", "~을 의뢰"처럼 동사 줄기로 끝낸다. 출력: "2. 위 근거에 의거, {purpose}하고자 하오니 결재하여 주시기 바랍니다."
- 문장을 직접 쓰려면 `request`에 번호 없이 문장 전체를 넣는다.

## sections (번호 항목)

`{"no": 1, "title": "추진 개요", "bullets": [...], "table": {...}, "schedule": {...}, "bulletsAfterTable": false}`. `no`는 1부터 차례로 붙인다.

기안 유형별 항목 순서와 각 항목의 출처:

| 유형 | 항목 순서 |
| --- | --- |
| 구매·용역 계약 의뢰 | 추진 개요 → 도입(과업) 내역 → 구매(계약) 방법 → 추진 일정 → 협조 요청 사항 |
| 기본계획 수립·입찰 시행 | 추진 배경 → 추진 방향 → 사업 개요 → 소요 예산 → 계약 방법 → 추진 일정 → 협조 요청 사항 |
| 결과 보고 | 개요 → 결과 → 향후 계획 → 협조 요청 사항 |

- 배경·현황·목적은 보고서·투자계획서에서 가져온다.
- 내역·예산 표는 견적서나 투자계획서의 투자규모 표에서 가져온다.
- 계약 방법·평가 방식·납품 기한은 투자계획서·제안요청서·과업내용서에서 가져온다.
- 일정은 보고서·투자계획서에서 가져온다.

**bullets**: `{"text": "라벨 : 내용", "sub": ["하위 내용"]}`
- `text`는 "ㅇ "으로, `sub`는 "- "로 나간다. `sub`가 `*`로 시작하면 각주("* ")가 된다.
- 문장은 명사형·개조식으로 끝낸다(예: "~필요", "~추진", "~예정"). 존댓말 서술문은 쓰지 않는다.
- 본문 한 줄은 약 45자(맑은 고딕 12pt)다. 한 항목은 2줄 이내로 쓰고, 다음 줄에 1~2글자만 넘어가지 않게 줄인다.

**table**: `{"unit": "천원, 부가세 별도", "head": [...], "rows": [[...], ...]}`
- 모든 행의 칸 수는 머리행과 같아야 한다.
- 첫 칸이 `합계`·`소계`인 행은 첫 값 앞까지 자동으로 가로 병합된다. 빈 칸은 `""`로 둔다.
- 첫 칸이 빈 행은 위 칸과 세로 병합된다(같은 구분 묶기).
- 금액은 천 단위 쉼표로 쓰고, 단위는 `unit`에 적는다. check는 합계 산수와 함께, 예산 합계(원 환산)가 견적서 공급가액·투자규모와 같은지 확인한다.
- `bulletsAfterTable: true`면 그 항목의 `bullets`가 표 아래 "* " 주석으로 나간다(예: "부가세 포함 154,000천원").

**schedule**: `{"year": "’26년~’27년", "months": ["10월", "11월", "12월"], "rows": [["입찰 공고", [1, 1, 0]], ...]}` → ● 표. 표시 칸 수는 `months` 수와 같아야 한다.

## attachments (첨부 목록)

첨부 폴더의 파일을 이름 순서대로 모두 넣는다. `{"no": 1, "type": "basis", "title": "...", "copies": 1, "file": "파일 이름"}`

| 첨부 | title 형식 |
| --- | --- |
| 공문 | `[시행번호] 제목(YYYY. M. D.)` |
| 보고서 | `[보고자료] 제목` |
| 투자계획서 | `[투자계획서] 사업명` |
| 견적서 | `견적서(업체명)` |
| 회의록·계약서·확인서 등 | 문서 제목 그대로 |

- 공문 여러 건을 한 첨부로 묶을 때는 `"files": [...]`를 쓰고, title 끝을 "각 1부"로 한다.
- 첨부 줄은 한 줄(약 50자)에 들어가야 한다. 넘치면 날짜를 빼거나 제목을 줄인다.
- 마지막 첨부 뒤에 ". 끝."이 자동으로 붙는다.

## approval

`{"drafter": "부서 이름", "line": [{"role": "부서원", "name": "…"}, {"role": "팀장", "name": "…"}, {"role": "부서장", "name": "…"}, {"role": "본부장", "name": "…", "mode": "전결"}], "cooperation": [{"dept": "경영기획부"}]}`

- 아직 올리지 않은 기안이므로 `date`는 비운다.
- 결재 칸과 협조 칸은 각각 8개다. 전결권자(본부장 전결, 사장 결재 등)는 사용자에게 확인한다.

## footer

`{"docNo": "", "date": "", "org": {"tel": "02-767-8114"}, "email": "부서메일@koscom.co.kr"}`

- 시행 전이라 `docNo`·`date`는 비운다. `email`을 비우면 연락처 칸이 빈다(check WARN).
